# PC全文検索 v2

OllamaやEmbeddingを使わず、ユーザー文書を一度だけ抽出してSQLite FTS5で検索するローカルアプリです。既存の`file_metadata.db`や旧スクリプトは変更しません。

## GitHubから取得した場合

`config.json`はPC固有の検索対象や除外パスを含むため、Gitには登録しません。
`start_search.cmd`を初めて実行すると、`config.example.json`から自動作成されます。
既定の検索対象は`%USERPROFILE%\Documents`です。起動後、右上の「管理」から
実際の検索対象を確認・変更してください。

手作業で作成する場合は次のようにコピーします。

```powershell
Copy-Item config.example.json config.json
```

## できること

- 対象フォルダを走査し、索引前に推定DB容量を表示
- PDF、Excel、Word、PowerPoint、CSV、TXTの本文抽出
- 日本語をJanomeで分かち書きしてFTS5検索
- 頻出語でも全一致チャンクを並べ替えず、関連度上位候補から高速に結果を作成
- ファイル追加・変更・削除の差分更新
- ヒット箇所、元ファイル、保存場所をローカルWeb画面で確認
- DB容量、索引件数、抽出失敗件数を表示
- 巨大文書は設定した文字数で安全に打ち切り、切り詰め状態を記録
- 初回索引は軽い文書から処理し、既定2プロセスで抽出・日本語解析を並列化
- Web画面から索引作成を安全に停止し、永続化した未処理分だけを再開
- 本文一致をファイル名・保存場所だけの一致より優先して表示
- 上位50件から追加読込、日付・場所・抽出状態・本文ありで絞り込み
- 同一本文のコピーを折りたたみ、文書内の別ヒットを前後移動
- 管理画面から検索対象、除外、容量、抽出失敗、巨大文書を確認

Wordは`.docx`と旧形式`.doc`、PowerPointは`.pptx`と旧形式`.ppt`が対象です。
旧形式は、PCにインストール済みのMicrosoft Word／PowerPointを読み取り専用・
マクロ無効でバックグラウンド利用します。OfficeがないPCでは、その旧形式だけが
抽出エラーになり、他の索引処理は継続します。Excelは`.xlsx`と旧形式`.xls`の
両方に対応します。

## セットアップ

### 推奨：移動可能な起動方法

`setup_search.cmd` をダブルクリックします。Python 3.11の専用実行環境を
`%LOCALAPPDATA%\PCFullTextSearch\runtime` に作成し、必要モジュールを
インストールします。初回だけインターネット接続が必要です。

セットアップ後は `start_search.cmd` のダブルクリックだけで検索画面を起動できます。
プログラムフォルダを移動しても、起動ファイル自身の場所を基準に動作します。
同じPC内であれば専用実行環境と検索DBをそのまま再利用します。

必要モジュールは次の8個です。付随する依存モジュールはpipが自動導入します。

- Flask 3.1.2：Web画面
- Janome 0.5.0：日本語解析
- openpyxl 3.1.5：Excel `.xlsx`
- xlrd 2.0.2：Excel `.xls`
- pypdfium2 5.1.0：PDF
- python-docx 1.2.0：Word
- python-pptx 1.0.2：PowerPoint
- pywin32 312：旧形式Word／PowerPointをローカルOffice経由で読み取り

SQLite、CSV、TXT、並列処理はPython標準機能を使うため追加不要です。

従来どおり既存venvを使う場合:

```powershell
cd v2
..\venv\Scripts\python.exe -m pip install -r requirements.txt
```

venvは内部に作成場所の情報を持つため、venvフォルダ自体を別の場所や別PCへ
コピーして使う運用は推奨しません。このアプリでは実行環境をLocalAppDataへ分離し、
移動するのはプログラムフォルダだけにしています。

別PCへ移す場合は、そのPCにPython 3.11を入れて `setup_search.cmd` を再実行し、
`config.json` の対象フォルダを確認してください。対象フォルダは現在絶対パスで設定
されているため、別PCでドライブやユーザー名が変わる場合は修正が必要です。

設定は`config.json`です。最初は不動産フォルダだけを対象にしています。
検索DBは既定で `%LOCALAPPDATA%\PCFullTextSearch\search_index_v2.db` に作ります。
SQLite DBをSynologyDriveの同期対象外に置くことで、同期との競合や破損を避けます。
原文は移動も変更もしません。

プログラムを別ディレクトリへ移した場合でも、`database_path`が
`%LOCALAPPDATA%\PCFullTextSearch\search_index_v2.db`のままなら既存DBを
再利用します。既存DBの形式は起動時に自動拡張され、全文索引の作り直しは不要です。
別ディレクトリ側の`config.json`もそのまま利用できます。明示的に別の設定ファイルを
使う場合は次のどちらかを利用します。

```powershell
app.py --config "D:\任意の場所\config.json" serve
$env:PC_FULLTEXT_SEARCH_CONFIG = "D:\任意の場所\config.json"
start_search.cmd "D:\任意の場所\config.json"
```

`exclude_folder_names` は完全一致、`exclude_folder_globs` は `*_bk` のような
パターンでフォルダを除外します。既定では `00_old`、`01_old`、`*_bk`、
`*バックアップ*`、`venv*` など、バックアップ・開発環境として判定しやすい
フォルダを自動除外します。

賃料収集・分析用の巨大CSVも除外したい場合は、次の名前を
`exclude_folder_names` に追加できます。

```json
"不動産賃料情報取得",
"不動産賃貸価格予測",
"不動産賃貸グラフ"
```

これは分析データを検索したい可能性もあるため、既定では除外していません。

検索画面右上の「管理」では、次を画面から変更できます。

- 検索対象フォルダ
- 常に除外するフォルダ
- 巨大CSV・Excelを「全文」「先頭行」「ファイル名のみ」「除外」にする設定
- 1文書の最大抽出文字数、最大ファイルサイズ、並列数
- アプリ起動中の自動差分更新間隔（0で無効）

除外候補は自動適用しません。対象文書数と本文容量を表示し、確認後に設定へ
追加します。設定変更後は差分更新を実行してください。対象や除外条件が変わった
場合、更新完了までは旧対象の文書を検索結果へ混在させません。

自動差分更新は検索アプリが起動している間だけ動作します。Windowsへ常駐サービスや
タスクを無断登録しない設計です。ログオン時にも自動起動したい場合は、動作確認後に
`start_search.cmd`のショートカットをWindowsのスタートアップへ登録してください。

## 使い方

容量調査（ファイルは変更せず、DBも作成しません）:

```powershell
..\venv\Scripts\python.exe app.py inventory --sample-per-type 10
```

最初の50件だけ索引して試す:

```powershell
..\venv\Scripts\python.exe app.py index --limit 50
```

全件を差分索引:

```powershell
..\venv\Scripts\python.exe app.py index
```

前回の走査で既に見つけた未処理文書だけを再開:

```powershell
..\venv\Scripts\python.exe app.py index --resume
```

Web画面には「全体を確認」と「続きから」の2方式があります。「全体を確認」は
新規・変更・削除を漏れなく検出する通常更新です。「続きから」は、前回の走査中に
DBへ記録済みの未処理文書だけを直接処理するため、全ファイル確認を省略できます。
ただし、停止前にまだ走査していなかった場所の変更は検出しないため、定期的な
「全体を確認」は必要です。

索引中は「全体を確認」が「■ 停止」に変わります。停止は現在の
小単位処理を安全に終了してから反映されるため、巨大なOffice文書では数秒待つ
場合があります。完了済みのファイルは保持され、未処理キューもDB内に残ります。

並列数は `config.json` の `index_workers` で設定します。既定値は2です。
SynologyDriveの読み出し負荷とメモリ使用量を抑えるため、最初からCPU数最大には
していません。通常は2、余裕があれば4までが目安です。

差分更新では全対象ファイルの存在・サイズ・更新日時を確認しますが、本文の再抽出は
新規・変更・抽出設定が変わったファイルだけです。対象フォルダや除外条件だけを変えた
場合は、残るファイルの既存本文を再利用します。小規模な差分更新ではDB全体の
FTS最適化も省略します。削除検出のための全ファイル確認は必要で、特にNASでは
ファイル一覧と属性取得の時間が残ります。

OneDriveなどのオンライン専用ファイルでは、除外フォルダ・除外ファイル・対象外の
拡張子を先に判定します。そのため、対象外ファイルの本文を開いて一括ダウンロード
することはありません。対象になった新規・変更ファイルは本文抽出時にだけ開くため、
オンライン専用ならそのファイル単位でダウンロードが発生します。全体確認中の
サイズ・更新日時の取得は本文読込ではありませんが、クラウド同期ソフト側の仕様に
よってはメタデータ通信が発生する場合があります。

コマンドライン検索:

```powershell
..\venv\Scripts\python.exe app.py search "給湯器 修繕"
```

検索画面:

```powershell
..\venv\Scripts\python.exe app.py serve
```

通常利用では、代わりに次をダブルクリックします。

```text
start_search.cmd
```

ブラウザで `http://127.0.0.1:8765` を開きます。LANには公開しません。
同じポートで既に同じDBのサーバーが動いている場合は、二重起動せず既存画面を
開きます。異なるconfigやDBのサーバーが動いている場合は、その旨を表示して停止します。

通常の「関連度」順では、FTS5から順位付き候補を段階的に取得し、必要な件数が
揃った時点で検索を終了します。頻出語でも全一致チャンクを最後まで並べ替えないため、
大規模DBでの応答時間を短縮します。更新日・名前・サイズ順は全該当文書に対する
厳密な並び替えを維持するため、非常に広い検索では関連度順より時間がかかります。

## 容量の考え方

本文そのものに加えて全文検索用の逆引き索引を保存するため、DBは抽出テキストより大きくなります。容量調査ではサンプル抽出から本文量を推定し、DB容量を本文量の1.3～2.0倍として表示します。

## 安全設計

- DBは原本ではなく再構築可能な検索キャッシュとして扱います。
- DBは同期フォルダの外に置きます。同期・バックアップするのは原文だけで十分です。
- `venv`、`.git`、`node_modules`、キャッシュ、作業用インポートフォルダなどを除外します。
- Web画面は`127.0.0.1`だけで待ち受けます。
- ファイルを開くAPIは、DBに登録済みのパスだけを対象にします。
